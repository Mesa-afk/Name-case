# ТТК — Карта пространства

Сервис для навигации внутри зданий и на мероприятиях: интерактивные 2D/3D-планы, панорамы 360°, маршруты между этажами и корпусами, офлайн-режим. Сделан по ТЗ кейса «Карта пространства» (ТрансТелеКом).

## Быстрый старт

```bash
npm install
npm start          # http://localhost:3000
```

Нужен Node.js 18+ (на Node 22+ данные хранятся во встроенном SQLite, на более старых — в JSON-файле).

| Роль | Вход |
|------|------|
| Организатор / администратор | `admin@ttk.ru` / `admin2026` или код доступа `admin2026` |
| Посетитель | `alexey@ttk.ru` / `ttk2026` |

Переменные окружения — см. `.env.example` (`PORT`, `JWT_SECRET`, `ADMIN_ACCESS_CODE`).

Данные демо-площадок создаются автоматически при первом запуске. Если в `server/database/storage/` осталась база от предыдущей версии проекта, сбросьте её командой `npm run reset-db` — сервер заново засеет её актуальными данными.

## Что реализовано по ТЗ

**Посетитель**
- Каталог площадок (бизнес-центр, выставка, отель, IT-хаб), поиск по залам, стендам и Wi-Fi.
- Векторный 2D-план этажа и режим 3D-наклона; переключение корпусов, этажей и общей территории.
- Точки интереса по категориям (входы, залы, стенды, стойки обслуживания, Wi-Fi, лифты) с описанием.
- Маршрут из точки А в точку Б (алгоритм Дейкстры по графу коридоров): внутри этажа, между этажами через лифты, между зданиями через территорию. Пошаговые подсказки, расстояние и время в пути.
- Просмотр панорам 360°: обзор перетаскиванием, зум, автоповорот, информационные точки и переходы между панорамами.
- «Пройти путь в 360°»: последовательный просмотр панорам вдоль построенного маршрута.
- Офлайн-режим (PWA + Service Worker): карта и панорамы кэшируются на устройстве.
- Интерфейс в первую очередь для телефона: нижняя навигация, жесты, переключатель «План / Маршрут».

**Организатор** (защищено JWT, пароли хранятся в виде bcrypt-хэшей, есть ограничение частоты попыток входа)
- Редактор 2D-плана: стены, помещения, проходы, окна, точки интереса, граф коридоров, линейка; привязка к сетке.
- Загрузка готового плана подложкой и автоматическое распознавание плана по изображению.
- Добавление этажей (с лифтовым переходом) и корпусов (с переходом через территорию).
- Мастер съёмки панорамы телефоном: 8 секторов с подсказками и компасом, сшивка кадров в 360° прямо в браузере. Можно загрузить и готовую панораму.
- Расстановка точек на панорамах (описание или переход в другую панораму).
- Простая 3D-модель помещения по фотографиям.
- Публикация: постоянная ссылка `/s/:id`, QR-код, код `<iframe>` для встраивания (`/embed/:id`). При сохранении изменений ссылка остаётся прежней.
- Скрытие карты (черновик) и PIN-код доступа для посетителей.
- Статистика: просмотры карты, точек и панорам, построенные маршруты, офлайн-сессии, активность по часам, популярные места.

## Связка фронтенда и бекенда

Фронтенд (`public/index.html` + `js/app.js`) — это Alpine.js-приложение, которое работает поверх REST API, а не на локальных моках:

| Действие в интерфейсе | Запрос к бекенду |
|-----------------------|------------------|
| Вход по email и паролю | `POST /api/auth/login` → JWT в `localStorage`, пользователь из ответа |
| Регистрация | `POST /api/auth/register` → JWT, роль `visitor`/`organizer` |
| Вход в админ-панель по коду | `POST /api/auth/admin-unlock` (код `admin2026`) → JWT организатора |
| Перезагрузка страницы | `GET /api/auth/me` — сессия восстанавливается по токену |
| Выход | токен удаляется из браузера (JWT stateless) |
| Каталог и карта | `GET /api/spaces` (с JWT организатора видны и черновики) |
| Карта под PIN-кодом | `GET /api/spaces/:id?pin=...` |
| Кнопка «Сохранить изменения» | `PUT /api/spaces/:id` — постоянная ссылка `/s/:id` не меняется |
| Загрузка планировки (SVG/PNG) | `POST /api/uploads/file` → `PUT /api/spaces/:id` |
| Просмотры карты, точек, панорам, маршруты | `POST /api/analytics/event` (`map_view`, `poi_view`, `pano_view`, `route_built`) |
| График и карточки аналитики | `GET /api/analytics/summary` (только организатор) |
| Офлайн-режим | события копятся в `localStorage`, при возврате в сеть уходят на сервер + событие `offline_sync` |

Если сервер или сеть недоступны, приложение продолжает работать на локальном кэше из `js/spaces-data.js` (офлайн-режим PWA), а затем подтягивает данные с сервера.

## API

| Метод | Путь | Доступ |
|-------|------|--------|
| POST | `/api/auth/register`, `/api/auth/login`, `/api/auth/admin-unlock` | все |
| GET | `/api/auth/me` | авторизованные |
| GET | `/api/spaces`, `/api/spaces/:id?pin=` | все (с учётом публикации и PIN) |
| POST / PUT / DELETE | `/api/spaces[/:id]` | организатор |
| POST | `/api/analytics/event` | все |
| GET | `/api/analytics/summary` | организатор |
| POST | `/api/uploads/file`, `/api/uploads/dataurl` | организатор |
